# Промпт 04. Единый Движок Очереди Для TUI И GUI

Ты работаешь в репозитории `goMH`. Целевая версия языка: `Go 1.25.1`.

## Цель этапа

Оставить в проекте один основной движок очереди и убрать расхождение между TUI и GUI по модели выполнения задач.

## Контекст

Сейчас в проекте есть `taskqueue` и отдельный GUI-менеджер задач. Это приводит к дублированию логики, отличающемуся поведению и усложняет поддержку.

## Что нужно сделать

1. Выбрать `taskqueue` как основной движок или зафиксировать другой единый runtime, но в итоге должен остаться один источник истины.
2. Перевести GUI на общий движок через адаптер, а не через отдельную реализацию очереди.
3. Сохранить текущую семантику:
   - параллельные non-exclusive задачи;
   - блокировку между `Exclusive`;
   - снапшоты задач;
   - прогресс и статусы;
   - логирование завершения задач в общий лог приложения.
4. Убедиться, что TUI dashboard и GUI продолжают работать поверх одного runtime API.
5. Не допустить регресса по UX в текущих интерфейсах.

## Важные места кода

- `taskqueue/queue.go`
- `taskqueue/queue_test.go`
- `gui/taskmanager.go`
- `gui/mainwindow.go`
- `tui/queue_dashboard.go`

## Критерии готовности

- В проекте не осталось двух независимых очередей выполнения.
- GUI и TUI используют один и тот же runtime-задач.
- Поведение `Exclusive` и параллельных задач покрыто тестами.
- `go test ./...` проходит.

## Что показать в отчете

- Что осталось единым движком.
- Как GUI теперь подключается к общей очереди.
- Какие файлы/типы стали адаптерами, а какие удалены.
- Какие тесты добавлены или обновлены.
