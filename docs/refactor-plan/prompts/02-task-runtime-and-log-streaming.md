# Промпт 02. Task Runtime И Поток Логов

Ты работаешь в репозитории `goMH`. Целевая версия языка: `Go 1.25.1`.

## Цель этапа

Сделать правильную модель выполнения и отмены задач, а также вынести просмотр логов в отдельный универсальный механизм потоковой выдачи.

## Основные требования

- Отмена задач должна строиться на нормальном `context.Context`.
- Приватные обходные интерфейсы для отмены нужно убрать или изолировать как временный адаптер.
- Просмотр логов — это не обычная queue-задача, а отдельная параллельная операция.
- Просмотр лога должен уметь писать в:
  - TUI;
  - GUI;
  - файл;
  - консоль;
  - чистый `stdout` для будущего `-cli`.
- Логи нельзя использовать как источник состояния выполнения.

## Что нужно сделать

1. Пересмотреть контракт `core.TaskContext` и/или ввести новый runtime-контракт задачи.
2. Добавить поддержку `context.Context` в выполнение задач.
3. Перевести отмену скачивания и других длительных операций на новую модель.
4. Спроектировать и реализовать отдельный сервис потокового чтения логов.
5. Переделать `ServiceUtils` так, чтобы просмотр логов использовал этот сервис, а не собственный special-case цикл.
6. Убедиться, что просмотр логов может запускаться параллельно с обычной работой программы.
7. Разделить:
   - общий лог приложения;
   - runtime-события задач;
   - пользовательский просмотр внешних лог-файлов.

## Важные места кода

- `core/types.go`

- пакет с console queue runtime
- `modules/serviceutils/serviceutils.go`
- `tui/context.go`
- `gui/context.go`

## Критерии готовности

- У задач есть нормальный cancelable runtime-контекст.
- Просмотр логов больше не завязан на `signal.NotifyContext(context.Background())`.
- Просмотр логов можно запустить в любой момент, не блокируя очередь.
- Есть хотя бы один чистый sink для `stdout`.
- `go test ./...` проходит.

## Что показать в отчете

- Новый контракт выполнения задачи.
- Как теперь устроена отмена.
- Как запустить поток логов в `stdout`.
- Какие части `ServiceUtils` упрощены или переиспользуют новый сервис.
