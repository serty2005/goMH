# Промпт 03. Единый Контракт Модулей И Реестр

Ты работаешь в репозитории `goMH`. Целевая версия языка: `Go 1.25.1`.

## Цель этапа

Упростить добавление модулей и убрать архитектурную зависимость от concrete types, сохранив весь текущий функционал.

## Что хотим получить

- единый контракт для модулей;
- единый реестр модулей;
- единый способ конфигурации и постановки задачи;
- отсутствие type-switch по конкретным типам при работе очереди;
- единую точку входа для повторяющейся логики queue plumbing.

## Что нужно сделать

1. Проанализировать текущие отличия между модулями `Run`, `Configure`, `Execute`.
2. Ввести новый интерфейс или набор интерфейсов уровня приложения для queue-capable модулей.
3. Перевести текущий механизм регистрации модулей на единый реестр.
4. Убрать ручной type-switch из console queue слоя.
5. Схлопнуть повторяющиеся `enqueue*Task` в одну универсальную точку постановки задачи.
6. Сохранить особенности:
   - `Exclusive`;
   - сигнатуры задач;
   - заголовки задач;
   - специальные результаты вроде автоперехода к просмотру лога.

## Подсказка по направлению

Хороший итог этого этапа:
- модуль описывает себя сам;
- слой приложения только берет модуль из реестра по `ID`;
- generic builder создает `TaskSpec` и общий runtime;
- UI не знает concrete type модуля.

## Важные места кода

- `core/types.go`
- новый пакет с queue runtime
- `main.go`
- `gui/form_*`
- `modules/*`

## Критерии готовности

- Новый модуль можно подключить через реестр без редактирования type-switch.
- Повторяющийся код enqueue обобщен.
- Постановка задач в очередь идет через одну общую точку.
- `go test ./...` проходит.

## Что показать в отчете

- Новый модульный контракт.
- Как теперь регистрируется модуль.
- Какая единая функция или сервис отвечает за постановку задач.
- Какие concrete-зависимости удалось удалить.
