# Промпт 05. Финальная Зачистка И Проверка

Ты работаешь в репозитории `goMH`. Целевая версия языка: `Go 1.25.1`.

## Цель этапа

После основных архитектурных изменений убрать техдолг, закрыть дублирование и зафиксировать итоговую структуру проекта.

## Что нужно сделать

1. Удалить мертвые API и неиспользуемые обертки, оставшиеся после миграции.
2. Свести к минимуму глобальные mutable output-hook’и в `assetmgr`, `dependencies`, `winutils`.
3. Привести крупные UI-обработчики к более поддерживаемому виду там, где это стало возможно после предыдущих этапов.
4. Обновить документацию проекта:
   - структура очереди;
   - логирование;
   - модульный контракт;
   - просмотр логов;
   - новый конфиг.
5. Закрыть тестами основные сценарии.

## Минимальный набор сценариев для проверки

- запуск приложения с включенным и выключенным файловым логированием;
- постановка задачи в очередь из TUI;
- выполнение задачи из GUI через общий runtime;
- отмена длительной задачи;
- параллельная работа обычных задач и просмотра логов;
- вывод лог-стрима в `stdout`;
- запись завершения модулей в общий лог утилиты.

## Итоговые артефакты

- очищенная структура пакетов;
- обновленный `README.md`;
- при необходимости краткая миграционная заметка по конфигу;
- список убранных временных адаптеров.

## Критерии готовности

- Очевидные дубли удалены или сведены к общему слою.
- В проекте нет мертвых обходных механизмов прошлой архитектуры.
- Документация соответствует реальному коду.
- `go test ./...` проходит.

## Что показать в отчете

- Какие дубли удалены.
- Какие временные адаптеры еще остались и почему.
- Какие сценарии реально проверены командами.
- Какие риски остаются после рефакторинга.
