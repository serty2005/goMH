# Промпт 01. Runtime И Логирование

Ты работаешь в репозитории `goMH`. Целевая версия языка: `Go 1.25.1`.

## Цель этапа

Подготовить базовый runtime-слой для дальнейшего рефакторинга:
- убрать `console_queue.go` из корня проекта;
- сделать централизованное логирование через отдельный сервис;
- добавить конфигурацию для отключения файлового логирования;
- вернуть контроль завершения процесса в `main`;
- сохранить текущий функционал.

## Ограничения

- Не ломай существующие сценарии запуска.
- Не меняй поведение модулей без необходимости.
- Новый конфиг логирования добавляй с переходной совместимостью со старым `log_level`.
- Логи не должны использоваться для функциональности, только для наблюдаемости и диагностики.
- Все комментарии, логи и сообщения — на русском языке.

## Что нужно сделать

1. Перенести код из `console_queue.go` в отдельный пакет приложения.
2. Выбрать и зафиксировать новое место для этого кода. Предпочтительный вариант: `app/consolequeue`.
3. Переделать пакет `logging` так, чтобы он:
   - принимал структурированный конфиг;
   - умел отключать запись в файл;
   - возвращал ошибку наверх вместо `os.Exit`;
   - при необходимости возвращал `cleanup`/`Close`.
4. Расширить конфиг в `config/config.go` и актуализировать `config.json`.
5. На переходный период поддержать старое поле `log_level`, если новая секция `logging` не задана.
6. Убрать прямое завершение процесса из нижних пакетов и оставить это решение только в `main`.
7. Встроить в общий лог события запуска и завершения модулей/задач, но не через чтение task-логов, а через явные runtime-события или централизованный вызов логгера.

## Ожидаемые изменения по файлам

- `main.go`
- `config/config.go`
- `config.json`
- `logging/logging.go`
- новый пакет для console queue вместо корневого файла
- при необходимости `README.md` с кратким описанием новой секции конфига

## Критерии готовности

- В корне проекта больше нет `console_queue.go`.
- `logging.Init` не завершает процесс внутри пакета.
- В конфиге есть опция отключения логирования в файл.
- `main` является единственной точкой, где принимается решение о завершении приложения.
- `go test ./...` проходит.

## Что показать в отчете

- Куда переехал `console_queue.go`.
- Как теперь выглядит конфиг логирования.
- Какие именно места больше не используют `os.Exit`/`panic`.
- Как фиксируется завершение модулей в общем логе.
