# goMH - Мультитул для техподдержки iiko и Syrve

## Описание

goMH - это консольное приложение для автоматизации задач технической поддержки систем iiko и Syrve. Приложение предоставляет модульную архитектуру с различными инструментами для работы с установками, сервисами, сетевыми настройками и оборудованием.

## Архитектура

### Основные компоненты

- **main.go** - точка входа приложения
- **core/** - основные типы и интерфейсы
- **modules/** - модули для различных функций:
  - `iiko` - работа с дистрибутивами iiko
  - `regime` - управление модулем ЧестныйЗнак
  - `frpc` - проброс портов через FRPC
  - `remoteaccess` - удаленный доступ
  - `serviceutils` - утилиты для работы с сервисами
  - `dto` - драйверы АТОЛ
  - `utm` - установка УТМ
  - `vcomcaster` - работа с VComCaster
- **tui/** - текстовый пользовательский интерфейс
- **winutils/** - утилиты для работы с Windows
- **config/** - система конфигурации
- **assetmgr/** - менеджер ресурсов и загрузок

### Интерфейсы

- **Installer** - интерфейс для всех модулей
- **WinUtils** - интерфейс для Windows-операций
- **AssetManager** - интерфейс для управления ресурсами

## Требования

- **Go 1.21+** для сборки
- **Windows** с правами администратора для запуска
- **.NET Framework 4.8+** для некоторых модулей

## Сборка

### Локальная сборка

```bash
# Клонирование репозитория
git clone <repository-url>
cd goMH

# Установка зависимостей
go mod download

# Сборка
go build -o goMH.exe ./...
```

### Сборка через GitHub Actions

Проект использует GitHub Actions для автоматизированной сборки и тестирования:

1. **CI Workflow** (`.github/workflows/ci.yml`)
   - Тестирование на нескольких версиях Go
   - Сборка для Windows
   - Проверка безопасности (Gosec)
   - Линтинг (golangci-lint)
   - Проверка зависимостей
   - Автоматическое создание релизов

2. **Windows Compatibility Check** (`.github/workflows/windows-check.yml`)
   - Проверка совместимости с Windows
   - Тестирование Windows-специфичных функций
   - Проверка прав администратора
   - Анализ системных требований

## Запуск

```bash
# Запуск с локальной конфигурацией
goMH.exe -config config.json

# Запуск с удаленной конфигурацией
goMH.exe
# (автоматически скачает config.json с удаленного сервера)
```

**Важно:** Приложение требует прав администратора для корректной работы со службами Windows, оборудованием и системными настройками.

## Модули

### Доступные модули

1. **iiko** - Установка и обновление дистрибутивов iiko (Front, Back, Card)
2. **Regime** - Установка и настройка модуля ЧестныйЗнак
3. **FRPC** - Настройка проброса портов через Fast Reverse Proxy
4. **RemoteAccess** - Настройка удаленного доступа
5. **ServiceUtils** - Утилиты для работы с Windows-сервисами
6. **DTO** - Установка драйверов АТОЛ
7. **UTM** - Установка и настройка УТМ
8. **VComCaster** - Работа с VComCaster

### Конфигурация модулей

Модули настраиваются через файл `config.json`:

```json
{
  "modules": [
    {"id": "iiko"},
    {"id": "regime"},
    {"id": "frpc"}
  ],
  "iiko_config": {
    "base_ftp_path": "/distr/iiko",
    "components_to_find": [...]
  }
}
```

## CI/CD

### Автоматическая сборка

При пуше в ветки `main` или `develop` автоматически запускаются:

1. **Тестирование** - проверка кода на разных версиях Go
2. **Сборка** - создание Windows-бинарника
3. **Проверка безопасности** - сканирование на уязвимости
4. **Линтинг** - проверка стиля кода
5. **Создание релиза** - автоматический релиз с артефактами

### Проверка совместимости

Отдельный workflow проверяет:

- Совместимость с Windows
- Доступность Windows API
- Права администратора
- .NET Framework
- Windows Defender
- COM-порты и оборудование

## Разработка

### Структура проекта

```
goMH/
├── main.go                 # Точка входа
├── core/types.go          # Основные интерфейсы
├── modules/               # Модули приложения
│   ├── iiko/             # Модуль iiko
│   ├── regime/           # Модуль Regime
│   ├── frpc/             # Модуль FRPC
│   └── ...
├── tui/                  # Пользовательский интерфейс
├── winutils/             # Windows-утилиты
├── config/               # Конфигурация
├── assetmgr/             # Менеджер ресурсов
└── .github/workflows/    # GitHub Actions
```

### Добавление нового модуля

1. Создать пакет в `modules/`
2. Реализовать интерфейс `core.Installer`
3. Добавить в конфигурацию
4. Зарегистрировать в `main.go`

## Безопасность

- Все зависимости проверяются на уязвимости
- Код проходит статический анализ
- Используются только проверенные внешние библиотеки
- Требуются права администратора для предотвращения несанкционированного доступа
