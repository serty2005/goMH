# goMH - Мультитул для технической поддержки

**goMH** - это специализированный инструмент для технической поддержки систем iiko и Syrve. Программа предоставляет удобный интерфейс для автоматизации рутинных задач, установки программного обеспечения и диагностики систем в среде Windows.

## Назначение проекта

goMH создан для упрощения работы технических специалистов при обслуживании систем автоматизации ресторанов и торговли. Программа объединяет в себе множество инструментов, которые обычно выполняются вручную или с помощью различных скриптов.

## Основные возможности

- **Автоматизированная установка ПО**: Установка продуктов iiko, модулей ЕГАИС, средств удаленного доступа
- **Работа с обновлениями**: Автоматический поиск и установка патчей для iiko
- **Диагностика и мониторинг**: Сбор логов, очистка временных файлов, мониторинг процессов (tail -f)
- **Настройка оборудования**: Установка драйверов для ФР Атол и виртуальных COM-портов для сканеров ШК.
- **Сетевая инфраструктура**: Настройка проброса портов, утилит для удаленного доступа, агента для сбора информации о системе

## Требования к системе

- **Операционная система**: Windows 10/11
- **Права доступа**: Запуск от имени администратора обязателен
- **Сетевые возможности**: Доступ интернету для загрузки дистрибутивов

# Модули программы

## 1. iiko (Front, Back, Card)

Модуль для установки продуктов системы iiko - ведущей платформы автоматизации ресторанов и торговли в России.

### Особенности реализации

- **Автоматическое сканирование FTP**: Поиск доступных версий продуктов на FTP-сервере (iiko_config)
- **Интеллектуальное меню**: Динамическое формирование списка доступных компонентов
- **Система патчинга**: Автоматический поиск и применение патчей для iikoFront после установки
- **Логирование установки**: Подробное протоколирование процесса установки с сохранением логов

### Доступные компоненты

- **iiko Front**: Кассовый модуль для работы с кассами и официантами
- **iiko Back**: Административный модуль для управления системой
- **iiko Card**: Специализированное решение для работы с картами лояльности

### Процесс работы

1. Сканирование FTP-сервера на наличие дистрибутивов
2. Выбор версии и компонента для установки
3. Автоматический поиск доступных патчей (для Front)
4. Скачивание и запуск установщика
5. Применение выбранного патча (при выборе)
6. Автоматический запуск установленного приложения

### Управление плагинами iikoFront

Модуль поддерживает автоматическое управление плагинами после установки iikoFront.

#### Параметры конфигурации

- **`excluded_plugins`**: Список имен плагинов, которые будут исключены из всех операций (установка, обновление). Пример: `["Updater", "UpdaterAssistant", "WebServer", "Delivery", "iikoTransport"]`.
- **`auto_update_plugins`**: Список имен плагинов для автоматического обновления после установки iikoFront. Пример: `["DualConnector", "SberbankPlugin"]`.

#### Логика автообновления

После установки iikoFront выполняется автоматическое обновление плагинов из списка `auto_update_plugins`:

1. Определяется версия установленного iikoFront.
2. Загружается манифест плагинов с сервера обновлений.
3. Фильтруются плагины по совместимости с версией iikoFront.
4. Исключаются плагины из списка `excluded_plugins`.
5. Для каждого плагина из `auto_update_plugins` выбирается последняя доступная версия (максимальная `plugin_version`).
6. Выполняется обновление плагина с созданием резервной копии.

#### Особенности обработки архивов

При распаковке плагинов выполняется проверка на многоуровневые архивы (с глубокой иерархией папок). Если архив содержит более одного уровня вложенности, процесс останавливается с предложением ручной распаковки и установки.

## 2. Regime (Локальный модуль ЧестныйЗнак)

Модуль для установки и обновления системы Regime - локального компонента для работы с системой ЧестныйЗнак.

### Особенности реализации

- **Автоматическая проверка .NET Framework 4.8**: Установка недостающего компонента при необходимости
- **Режим переустановки**: Обнаружение существующей установки и предложение обновления
- **Аутентификация**: Запрос учетных данных администратора для корректной установки
- **Логирование**: Подробное протоколирование процесса установки

### Процесс работы

1. Проверка наличия .NET Framework 4.8
2. Установка .NET Framework при необходимости
3. Проверка существующей установки regime
4. Запрос учетных данных (только для новой установки)
5. Установка/обновление сервиса
6. Проверка корректности установки

## 3. Утилиты обслуживания (ServiceUtils)

Комплексный модуль для диагностики и обслуживания рабочих станций.

### Доступные утилиты

#### 3.1 Очистка временных файлов
Автоматизированная очистка временных файлов и кэша системы.

**Особенности:**
- Поддержка шаблонов путей (wildcards)
- Расчет освобождаемого пространства
- Безопасное удаление с подтверждением размера
- Определение путей в config.json в параметре MaintenanceConfig.TempPaths

#### 3.2 Сборщик логов в архив
Интеллектуальный сборщик логов с гибкой фильтрацией.

**Особенности:**
- Выбор периода сбора (в днях)
- Поддержка вложенных архивов (ZIP, GZIP, 7Z)
- Автоматическое определение директорий с логами на списка в config.json MaintenanceConfig.LogCollectorPaths
- Создание структурированного архива с сохранением иерархии

#### 3.3 Просмотр логов в реальном времени
Мониторинг лог-файлов с возможностью просмотра "хвоста" файлов.

**Особенности:**
- Автоматический поиск актуальных логов за текущий день
- Постраничный вывод последних строк
- Режим реального времени слежения за файлом
- Управление просмотром через горячие клавиши

#### 3.4 Патчи iikoFront
Автономная система применения патчей iikoFront.

**Особенности:**
- Автоматическое определение установленной версии
- Поиск актуальных патчей на сервере обновлений
- Создание резервных копий перед обновлением
- Восстановление бэкапа перед применением нового патча

#### 3.5 OrderCheck
Инструмент для диагностики и работы с бд iikoFront и Алкоплагина.

#### 3.6 FrontTools
Набор инструментов для выполнения проверок iikoFront в соответствии со статьями базы знаний.

**Особенности:**
- Автоматическое определение типа базы данных
- Выбор специализированной версии инструмента
- Работа с повышенными правами доступа

## 4. Драйвер для АТОЛ ФР (ДТО)

Модуль для установки драйвера Атол

### Особенности реализации

- **Автоматическое получение дистрибутива**: Загрузка актуальной версии через AssetManager (config.json > asset_catalog > DTO_Installer)
- **Гибкая настройка параметров**: Передача аргументов установки через конфигурацию (dto_config)

## 5. FRPC (Fast Reverse Proxy Client)

Модуль для настройки безопасного проброса портов через защищенный туннель.

### Особенности реализации

- **Автоматическая настройка NSSM**: Установка и настройка службы Windows
- **Интеллектуальный выбор портов**: Автоматический поиск свободных портов на сервере
- **Генерация конфигурации**: Автоматическое создание конфигурационных файлов
- **Управление службой**: Автоматический запуск и настройка автозапуска
- **Настройка сервера в config.json**: Отдельный раздел frpc_config для настройки своего сервера ([FRPS](https://github.com/fatedier/frp))

### Процесс настройки

1. Проверка существующей установки
2. Загрузка компонентов (FRPC + NSSM)
3. Определение архитектуры системы (x86/x64)
4. Запрос порта, который нужно пробросить и названия для данного подключения
5. Создание и запуск службы Windows

## 6. Средства удаленного доступа

Комплексный модуль для установки различных решений удаленного доступа с унифицированным интерфейсом.

### Доступные компоненты

#### 6.1 TeamViewer
Установка кастомного Host-клиента MyHoreca для удаленного доступа.

**Особенности:**
- Автоматический поиск актуальной версии через API
- Адаптивная загрузка для текущей архитектуры
- Тихая установка без вмешательства пользователя
- Ссылка указывается в config.json в разделе TeamViewerConfig.ShortURL

#### 6.2 LiteManager
Профессиональное решение для удаленного администрирования.

**Особенности:**
- Полностью тихая установка
- Конфигурация в менеджере ассетов config.json asset_catalog.LiteManager_Installer

#### 6.3 Getad Agent
Специализированное решение для сбора информации о рабочей станции и отправки данных на FTP-сервер MyHoreca.

**Особенности:**
- Автоматическое обнаружение и удаление старых версий
- Настройка триггеров автозапуска
- Интеграция с планировщиком задач Windows
- Исключение в Защитнике Windows для /getad

## 7. УТМ (ЕГАИС)

Модуль для установки Универсального Транспортного Модуля - обязательного компонента для работы с системой ЕГАИС.

### Особенности реализации

- **Автоматическое получение дистрибутива**: Загрузка актуальной версии через AssetManager (UTM_Installer)
- **Соответствие требованиям**: Полностью тихая установка

## 8. [VComCaster](https://github.com/symp1ex/VComCaster)

Специализированный модуль для зеркалирования вывода сканеров штрих-кодов через виртуальные COM-порты.

### Особенности реализации

- **Автоматическое создание виртуальных портов**: Установка и настройка com0com
- **Интеллектуальное определение устройств**: Автоматический поиск USB-COM-портов и запрос пользователю для выбора порта ШК
- **Генерация конфигурации**: Создание настроек для конкретного оборудования
- **Интеграция с iiko**: Автоматическое обновление конфигурации портов в iiko

### Процесс настройки

1. Установка драйверов виртуальных портов (com0com)
2. Определение подключенных USB-COM-портов (физический RS-232 не поддерживается)
3. Выбор целевого сканера из списка найденных устройств пользователем
4. Создание конфигурационного файла с оптимальными параметрами
5. Настройка автозапуска через планировщик задач
6. Автоматическое обновление конфигурации iiko (при наличии)

# Инструкции по использованию

## Запуск программы

1. **Права администратора**: Программа обязательно должна запускаться от имени администратора
2. **Конфигурация**: При первом запуске автоматически загружается файл конфигурации 
3. **Главное меню**: После запуска отображается меню с доступными модулями

## Конфигурация

Программа использует JSON-конфигурацию для настройки параметров модулей. По умолчанию файл config.json будет загружен [отсюда](https://f.serty.top/distr/installer/config.json) Структура конфигурации включает:

- Параметры подключения к серверам
- Настройки загрузки дистрибутивов
- Параметры установки модулей
- Пути к логам и временным файлам

#### IikoConfig

Раздел конфигурации для модуля iiko:

- `base_ftp_path`: Базовый путь к FTP-серверу для загрузки дистрибутивов iiko.
- `patches_base_url`: URL для загрузки патчей iikoFront.
- `components_to_find`: Список компонентов iiko для поиска на FTP.
- `card_pos`: Конфигурация для iiko Card.
- `excluded_plugins`: Список имен плагинов, исключаемых из всех операций (установка, обновление).
- `auto_update_plugins`: Список имен плагинов для автоматического обновления после установки iikoFront.

Вы можете сохранить config.json рядом с исполняемым файлом и он будет использован при запуске.
URL для загрузки определён в remoteConfigURL в main.go:107

# Для разработчиков

## Сборка проекта

### Требования

- Go 1.23 или выше
- Git для управления зависимостями

### Команды сборки

```bash
# Клонирование проекта
git clone https://github.com/serty2005/goMH.git
cd goMH

# Загрузка зависимостей
go mod download

# Быстрая сборка для разработки
go build -o goMH.exe .

# Запуск без сборки
go run .
```

### Структура проекта

```
goMH/
├── main.go              # Точка входа в приложение
├── core/
│   └── types.go         # Определения интерфейсов и базовых структур
├── modules/             # Реализация модулей
│   ├── dto/            # ДТО (драйвер Атол ФР)
│   ├── frpc/           # Fast Reverse Proxy Client
│   ├── iiko/           # Продукты iiko + система патчинга
│   ├── regime/         # Локальный модуль ЧестныйЗнак
│   ├── remoteaccess/   # Средства удаленного доступа
│   ├── serviceutils/   # Утилиты обслуживания
│   ├── utm/            # УТМ для ЕГАИС
│   └── vcomcaster/     # Работа со сканерами
├── assetmgr/           # Менеджер ресурсов и загрузок
├── config/             # Конфигурационные структуры
├── tui/                # Интерфейс пользователя
└── winutils/           # Утилиты для работы с Windows
```

## Расширение функциональности

### Добавление нового модуля

1. Создать директорию в `modules/`
2. Реализовать структуру `Module` с методами `ID()`, `MenuText()`, `Run()`
3. Зарегистрировать модуль в `main.go`
4. Добавить конфигурацию в файл конфигурации

### Пример структуры модуля

```go
type Module struct {
    Cfg *config.CustomConfig
}

func (m *Module) ID() string {
    return "CustomModule"
}

func (m *Module) MenuText() string {
    return "Описание модуля для меню"
}

func (m *Module) Run(am core.AssetManager, wu core.WinUtils) error {
    // Реализация логики модуля
    return nil
}
```


### Сборка с оптимизацией
```bash
go build -ldflags="-s -w" -o goMH.exe
```
